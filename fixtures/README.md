# Fixture corpus

These files are synthetic. They were generated by [`generate.sh`](generate.sh) and [`assemble.py`](assemble.py) in this directory. No third-party photograph, camera RAW, video, or ICC profile was copied in.

`SHA256SUMS` is the canonical digest list. `cargo test` checks every file against it.

## Tools used to generate the committed bytes

| Tool | Version |
| --- | --- |
| ExifTool | 12.76 |
| libheif / heif-enc | 1.17.6, x265 3.5 HEVC encoder |
| FFmpeg | 6.1.1-3ubuntu5 |
| ImageMagick `convert` | 6.9.12-98 Q16 |

Regenerating with different tool versions will not be bit-identical. Treat the committed bytes as the corpus. Update this table and `SHA256SUMS` together if you intentionally regenerate.

## Live Photo note

ExifTool 12.76 can write EXIF and XMP into a fresh HEIC. It will not create Apple maker notes, or a QuickTime Keys box, in a HEIC that does not already have them. The still therefore carries the pair UUID in XMP, and the movie carries the real `Keys:ContentIdentifier`. Discovery links the pair by filename (`IMG_0005.heic` + `IMG_0005.mov`), which is the same rule Albumen uses for Live Photos.
