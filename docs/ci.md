# CI

The round-trip job does not use `ubuntu-latest`. That label starts moving to Ubuntu 26.04 on 2026-10-19. The workflow pins `ubuntu-24.04` and also runs `ubuntu-26.04`.

ExifTool is Image-ExifTool **13.59**, SHA-256 `668ea3acececb7235fbd0f4900e72d5f12c9b07e5c778fd36cb1e9b5828fd65a`, installed by `scripts/install-exiftool.sh` from the SourceForge release tarball. The 12.76 tarball that generated the fixture bytes returns 404 from exiftool.org and from SourceForge, so the gate cannot pin 12.76. Fixture bytes are not regenerated. Metadata comparisons use this one binary on both the source and the copy.

MinIO stays at `RELEASE.2025-09-07T16-13-09Z`, SHA-256 `7c5bd8512c6e966455b1d198209358b2d191c77a83ab377c4073281065fb855f`, in `scripts/with-minio.sh`. The workflow downloads that binary and runs it. The tree does not contain MinIO source.

rclone stays at **v1.75.2**, zip SHA-256 `349ac8fba6ff65d6247043f1750cdcb518ec5d500ef91463a10d37c0ccdf3702`, in `scripts/install-rclone.sh`. The round-trip job uses that binary as the transport for SFTP and WebDAV (`rclone serve` on a local directory) and for B2. B2 has no local server and no paid account in CI, so that leg is rclone's S3 backend pointed at the same MinIO. The tree does not contain rclone source.

The Android camera-roll job runs on `ubuntu-24.04`. `scripts/install-android-sdk.sh` pins command-line tools `13114758`, SHA-256 `7ec965280a073311c339e571cd5de778b9975026cfcbe79f2b1cdcb1e15317ee`, from `https://dl.google.com/android/repository/commandlinetools-linux-13114758_latest.zip`. It then installs `platforms;android-35` and `build-tools;35.0.0`, which `sdkmanager` checks against Google's repository. `scripts/install-gradle.sh` pins Gradle `8.11.1`, SHA-256 `f397b287023acdba1e9f6fc5ea72d22dd63669d59ed4a289a29b1a76eee151c6`. The library is Android Gradle Plugin `8.7.3` and Kotlin `2.0.21`. `scripts/android-ci.sh` compiles the `backup` library and the `host` app, runs their unit tests, and assembles the host debug APK. The host test checks the permission decision. It does not click the system permission dialog.

The round-trip job also runs on `macos-14` (Apple silicon, arm64). That leg runs `cargo fmt`, `cargo clippy`, and `scripts/with-minio.sh cargo test --locked --all-targets`, the same suite as Ubuntu, including the S3 and rclone round-trips. Docker is not used. `scripts/with-minio.sh` downloads the pinned MinIO binary `minio.darwin-arm64.RELEASE.2025-09-07T16-13-09Z`, SHA-256 `7c3b3039b76e55a1b80935848ed83998d5e8d317374f87851f46a019ff5c0aa4`. `scripts/install-rclone.sh` downloads `rclone-v1.75.2-osx-arm64.zip`, SHA-256 `610ab7d48615135dfc60b763858b11a426a0d3d1160c1bb76fb0ae6011b02edd`. ExifTool is the same 13.59 tarball; the script checks it with `shasum -a 256` when `sha256sum` is absent. An OS without a pinned MinIO binary does not start Docker. The script prints that S3 will not run, sets `ALBUMEN_S3_UNAVAILABLE=1`, and the S3 tests return before they would panic. That fallback is not the macOS leg: macOS runs the full suite.

The round-trip job also runs on `windows-2025`. That label is pinned. It is not `windows-latest`. The job uses Git Bash and sets `core.autocrlf` to false before checkout so `cargo fmt` sees LF. It runs `cargo fmt`, `cargo clippy`, and `scripts/with-minio.sh cargo test --locked --all-targets`. `scripts/with-minio.sh` downloads `minio.windows-amd64.RELEASE.2025-09-07T16-13-09Z.exe`, SHA-256 `af709e6ba68488404e85acdd22a3030d0f5e56a108d4b27d744f18ceb50861b4`. `scripts/install-rclone.sh` downloads `rclone-v1.75.2-windows-amd64.zip`, SHA-256 `8a9db2bad1dc79a65b3348fd857069598e2aab7cf4d118b77b1df23055aff818`. ExifTool is the same 13.59 tarball. The `windows-2025` image supplies Perl. `scripts/install-exiftool.sh` keeps that pinned script and writes `exiftool.cmd` beside it. Rust resolves a bare `exiftool` only as `exiftool.exe`, so Albumen launches `exiftool.cmd` on Windows and that launcher runs the pinned script through `perl`. No ExifTool, MinIO, or rclone leg is skipped on this image. An architecture without a pinned Windows binary still sets `ALBUMEN_S3_UNAVAILABLE=1` and stays on the local filesystem.

NTFS stores modification times in 100 nanosecond ticks. `set_mtime` writes that tick and the copy check requires it back. A finer timestamp is not rounded further. The round-trip still requires SHA-256, the filename, `FileModifyDate`, and every embedded EXIF, XMP, IPTC, GPS, and QuickTime tag. ExifTool on Windows reports the creation time as `System:FileCreateDate` from the same stat field Unix reports as `System:FileInodeChangeDate`, so that tag is ignored with the other filesystem identity tags. `System:ZoneIdentifier` is the NTFS `Zone.Identifier` alternate data stream. A byte copy does not carry that stream, and the comparison ignores the tag. Paths inside manifests stay slash-separated. No test is skipped on Windows. Symlink creation uses the Windows symlink API. File identity uses the NTFS creation time, because `MetadataExt::file_index` is still unstable, where Unix tests use an inode. A manifest file, a receiver sidecar, and a receiver tombstone are fsynced and then renamed. Opening the parent directory to fsync that rename returns access denied for some Windows directories, including the process temp root and a library created under it. After the file sync and the rename, that denial is not a failed write.

`scripts/check-dest-writes.py` runs in the round-trip job before the tests. It fails when production Rust outside `ingest/src/dest.rs` creates, writes, renames, or removes a file. Test modules are stripped first. `bench/` is not scanned: it writes synthetic timing files and does not open a user archive.

`scripts/scan-no-network.sh` runs on `ubuntu-24.04` with rootless podman and strace. It is the socket and source-write proof for `albumen scan` and an `albumen-receive` dry-run. `scripts/sandbox-trial.sh` is the same shape against a copy of `fixtures/`. macOS has no Docker in this workflow, so the socket proof stays on Ubuntu.

The generated million-item tree is `cli/tests/raid_scale.rs`. It is `#[ignore]`, so a pull request does not create a million inodes and does not wait on that job. [`.github/workflows/raid-scale.yml`](../.github/workflows/raid-scale.yml) runs it on `macos-14` with `--ignored`, on `workflow_dispatch` and a weekly schedule. The job timeout is 180 minutes. The workflow does not set `ALBUMEN_RAID_ITEMS`. The ladder these jobs belong to is [test-ladder.md](test-ladder.md). What each binary can read, write, and reach is [threat-model.md](threat-model.md).

`.github/workflows/macos-binaries.yml` builds `albumen`, `albumen-mcp`, and `albumen-receive` on `macos-14` and uploads `albumen-macos-arm64.tar.gz`, `albumen-macos-arm64.tar.gz.sha256`, keyless cosign bundles, and GitHub artifact attestations to an existing GitHub release. A `v*` tag runs it. `workflow_dispatch` takes a release tag and defaults to `v0.1.0`. The upload uses `gh release upload --clobber` and does not move the tag. The build is reproducible-ish and is not claimed bit-identical. Verification and the notarization gap are in [release-verify.md](release-verify.md). The trial commands are in [trial-macos.md](trial-macos.md).

The iOS job runs `swift test --package-path mobile/ios` on `macos-14`. PhotoKit is a macOS framework, so the package builds there. This VM is Linux and cannot link Photos. If the macOS runner is rejected for billing, that job has to come out and this page has to say so.

`ALBUMEN_REAL_CORPUS` is not set in CI. `ingest/tests/real_corpus.rs` skips when it is unset, so the job stays green. Set it locally to a directory that contains media files and `sanitized.sha256` in sha256sum form. The test then checks each checksum and copy-verifies every listed file on the local filesystem and on MinIO, including SHA-256, filename, mtime, and an ExifTool dump. Live Photo pairs are detected from a shared ContentIdentifier. Sidecars are detected from the generic XMP and AAE names. Do not commit that directory, and do not put a real filename, checksum, or GPS value in the tree. `real-corpus/`, `fixtures/real-device/`, and `*.real-corpus` are gitignored. The synthetic fixture corpus is unchanged.

The `albumen-mcp image` job runs on `ubuntu-24.04`. `scripts/check-mcp-release.py` downloads `https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json` and validates [server.json](../server.json). The description must be the tagline and nothing longer. The version must match `mcp/Cargo.toml` and `ghcr.io/jay-the-maker/albumen-mcp:<version>`. The same script requires the default `/library` mount to be a required read-only bind, and the optional writable mount to be `/destination` rather than the library. The job then builds the Dockerfile and checks the entrypoint, the `io.modelcontextprotocol.server.name` label, and ExifTool. `scripts/check-library-mount.sh` runs that default mount and checks that create, modify, rename, and delete under `/library` fail while the host file stays unchanged. The job does not push.

`.github/workflows/publish-mcp.yml` runs only on a `v*` tag. It repeats the version check against the tag, pushes `ghcr.io/jay-the-maker/albumen-mcp:<version>` with `GITHUB_TOKEN`, installs mcp-publisher v1.8.1 by SHA-256, runs `mcp-publisher login github-oidc`, and publishes `server.json`. Actions in that workflow are pinned to commit SHAs.

Search and browse pagination is covered by `mcp` unit tests, including a synthetic library of one million empty items. That test checks that caption pages and a path query are complete, and that peak RSS stays within 32 MiB from 100,000 items to 1,000,000. The walker computes each path from its index, so the test does not create a million inodes. It finishes in seconds and runs on every pull request inside `cargo test`. A separate nightly job is not used.

The `performance regression` job runs on `ubuntu-24.04` only. It installs the pinned ExifTool and runs `cargo run --release --locked -p albumen-bench -- --check`. The harness repeats each measurement and drops a noisy sample. Runners differ by more than 10 percent in raw MB/s, so the gate compares Albumen with a same-run reference and fails when the copy, cold-search, or browse ratio is more than 10 percent worse than [bench/baseline.json](../bench/baseline.json). Warm search p50 and p95 are printed and are not a failure, because that ratio is not stable on these runners. The library in that job is 128 synthetic items, not 380,000. The budgets and the local 380,000-item command are in [performance-budgets.md](performance-budgets.md).

`philosophy-ack` runs on pull request open, edit, and synchronize. `scripts/check-philosophy-ack.py` reads the pull request body. It fails unless the body contains the checked line `- [x] I have read DESIGN_PHILOSOPHY.md and this change upholds it`, the checked lines `- [x] Sane defaults`, `- [x] No account required`, and `- [x] No nags`, and unless the text under `How this upholds it` is at least 20 characters and is not the template placeholder. HTML comments are ignored, so a checked box or an explanation hidden in a comment does not count. The workflow runs the script's `--self-test` before it reads the pull request. `scripts/check-dco.sh` reads `BASE..HEAD` on the pull request head (not the synthetic merge commit) and fails unless every commit message has a `Signed-off-by` line. It is a script in this repository. It is not a GitHub App.
